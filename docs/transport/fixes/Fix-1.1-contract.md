## 1. Guarantee

A POST to `/transport/book` with the same `idempotency_key` from the
same authenticated user produces exactly one `Booking` row. Any
subsequent submission of the same key returns the first booking's
`booking_reference` without creating a second row, without re-running
fare computation, and without any database write beyond an audit
entry.

## 5. Interface Contract

### Column
Booking.idempotency_key
type: VARCHAR(128)
nullable: TRUE
default: NULL

text

### Index
CREATE UNIQUE INDEX ix_booking_idem
ON transport_bookings (idempotency_key)
WHERE idempotency_key IS NOT NULL;

text

The partial index (WHERE clause) is required. It allows existing
rows with `NULL` idempotency_key to coexist while enforcing
uniqueness only on rows that carry a key.

### Form field
```html
<input type="hidden" name="idempotency_key" id="hIdempotencyKey" value="">
Placed inside #boltForm next to the other hidden inputs.

Client-side generation
On confirm screen mount (state c becomes active), generate
crypto.randomUUID() once and store in #hIdempotencyKey.

The value persists across re-renders of the same screen.

A fresh UUID is generated only when the user returns to state
a and starts a new booking.

Fallback for older browsers: if crypto.randomUUID is
undefined, use 'idem-' + Date.now() + '-' + Math.random().toString(36).slice(2).

Server-side dedupe (inside create_booking)
Before any fare calculation, before any DB write:

python
key = (data.get("idempotency_key") or "").strip() or None
if key:
    existing = Booking.query.filter_by(
        idempotency_key=key,
        user_id=customer_id,
        is_deleted=False,
    ).first()
    if existing:
        return {
            "success": True,
            "data": {
                "booking_id": existing.id,
                "booking_reference": existing.booking_reference,
                "idempotent_replay": True,
            },
        }
If key is present, it is written to Booking.idempotency_key at
insert time.

Behavior on hit
No new Booking row.

No new fare computation.

No new audit log entry other than an idempotent_replay=True
marker in booking_metadata.

Response contains the original booking_reference.

HTTP
Return HTTP 200 with the existing booking's booking_reference.

Not 201. Not 409. 200. The request succeeded; the resource
already existed; this is the correct status.

Audit
Append to booking_metadata on the existing booking (or on the
first creation for the replay case):

python
booking_metadata["idempotent_replay"] = True
booking_metadata["replayed_at"] = datetime.now(timezone.utc).isoformat()
